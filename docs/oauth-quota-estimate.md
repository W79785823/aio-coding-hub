# OAuth 账号额度预估

供应商列表的 OAuth 用量行显示 Codex / Claude 当前窗口的预估总额度与剩余额度。首页复用同一个组件。

参考 [Sub2API 的 Codex 周额度预估](https://github.com/Wei-Shaw/sub2api/blob/37067e8e340e9440d173a92b4faa05e8ce58368f/frontend/src/components/account/AccountUsageCell.vue#L853-L870)及[周期费用起点](https://github.com/Wei-Shaw/sub2api/blob/37067e8e340e9440d173a92b4faa05e8ce58368f/backend/internal/service/account_usage_service.go#L1545-L1550)。Sub2API 用窗口费用除以窗口累计已用比例；这条实现没有中途接入的百分比基线，金额预估只传给 OpenAI OAuth 的周窗口。

AIO 在此基础上为两个窗口分别记录采样基线，让中途升级、登录后的本地费用与上游百分比覆盖同一段时间：

```text
当前已用比例 = 100 - 当前上游剩余百分比
采样已用比例 = 当前已用比例 - 首次同步时的已用比例
预估总额度 = 首次同步后的本地采样费用 × 100 / 采样已用比例
预估剩余额度 = 预估总额度 × 当前上游剩余百分比 / 100
```

例如，首次同步时本周已用 20%，之后本地新增费用 $1、上游已用变为 25%，预估总额为 `$1 / (25% - 20%) = $20`，剩余约 `$20 × 75% = $15`。不能再用这 $1 除以整个周期的 25%，否则会把接入前的用量计入分母，得到偏低的 $4。

- 用上游重置时间减去窗口长度确定周期身份；Codex 优先采用上游 `limit_window_seconds`，缺省为 5 小时 / 7 天；Claude 为 5 小时 / 7 天。两个窗口独立保存首次同步时间和当时的已用比例，不互换或强制排序预估金额。
- 百分比和预估金额使用同一份窗口时长元数据。即使没有费用样本或估算查询失败，非标准窗口仍显示实际时长，不回退为“周”。
- 费用来自该来源账号成功、未排除且没有错误码的本地请求日志，包含日志中记录为使用该来源账号的跨 CLI 桥接请求；不根据当前桥接配置回溯归属。使用日志记录的 USD 费用口径（含请求当时的供应商费用倍率）。不查询或修改订阅余额，也不新增上游调用。
- 首次有效同步先保存基线，显示“待积累用量”；此后的费用和百分比都有增长即可估算，不需要等满 5 小时或一周。基线保存在数据库中，重启应用及正常 token 刷新均保留；显式重新登录、切换认证方式和断开连接会清除基线。周期起止时间变化、可信费用起点晚于基线或已用比例降至基线以下时重建采样。
- 升级后的首次同步也会建立基线，不使用无法确认归属的旧费用，原始日志保留。日志以秒记录请求起点，采样从首次同步的下一秒开始且不早于登录的可信费用起点，保守排除同秒及此前已开始的请求。
- 浏览器或设备码登录成功后，立即清除该供应商的旧用量缓存，再将新账号用量写入首页和列表共用的缓存；状态或用量读取失败时不沿用旧账号数据。断开连接也清除用量缓存，旧请求晚返回不会恢复旧数据；普通 token 刷新保留当前用量。
- 桥接来源随最终请求日志保存；升级时仅回填日志中能确认与最终供应商匹配的历史来源。直接请求和桥接请求分别按供应商与时间索引查询，同一请求不会重复计费。
- 采样费用和同期已用比例增量均为有效正数时才显示预估金额；部分请求缺少费用不会阻止整个窗口估算。悬停提示会说明采样费用、缺失费用的请求数，以及估值可能偏低。每次刷新按同一基线后的累计费用和用量增量重新计算，不保留上次估值作为回退。
- 没有采样费用、费用总额为零或已用比例没有增长时显示“待积累用量”；全部请求均缺少费用时显示“费用数据不足”；窗口自然到期后显示“已重置，待刷新”，不会沿用旧窗口金额。
- 手动重置成功后清除两个窗口的采样基线并递增快照版本，即使后续用量刷新失败也生效；界面清除旧金额，重置前尚未完成的查询不能恢复旧基线。下一次成功同步重新采样，无需再次消费重置次数。
- 费用估算只附加到界面查询和手动重置的返回值，在释放额度刷新锁后执行。网关自动额度刷新只保存真实额度，不等待金额统计；估算查询失败时保留正常的 OAuth 用量刷新和配额保护行为。附加估算前校验登录凭证和快照版本，持久化新基线时再以原基线、凭证和版本作条件更新，避免旧请求覆盖新账号或新周期的采样。

金额带 `~`，仅供参考，不代表上游承诺的美元余额。通过其他客户端使用账号、上游百分比取整或更新延迟、改变模型/费用倍率，仍会影响估算准确性。已有点数、重置次数及配额路由保护继续使用原有真实数据。
